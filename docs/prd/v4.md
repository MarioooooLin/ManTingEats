# PRD — ManTingEats v4（點餐客製化：加料／辣度）

> 狀態：**已定案**（2026-09-23）。本文件為 [mvp.md](mvp.md) 的擴充版本，新增「加料」與「辣度」客製化點餐能力，不修改既有模組範圍。

## 1. 需求摘要

**目標**：部分餐點可加料、可調辣度，但現行點餐表單走單一簡易樣式（品項＋數量＋自由文字備註），無法結構化記錄客製化內容。新增「客製化點餐」能力，依品項旗標決定走簡易表單或客製化表單，兩者並存。

**使用者情境**：仍為店長單人操作，現場點餐頻率高，客製化互動需盡量精簡，避免拖慢點餐速度。

## 2. 模組詳細規格

### 2.1 品項客製化設定（Menu 模組擴充）

**使用者故事**

- As a 店長, I want 設定某品項是否可加料、是否可調辣度, so that 點餐時系統自動呈現對應的表單。
- As a 店長, I want 維護一份全店共用的加料清單（名稱、加價）, so that 各品項點餐時可以勾選加料並自動計價。

**驗收標準**

- `MenuItem` 新增兩個旗標：`SupportsAddOns`（是否開放加料）、`SupportsSpiceLevel`（是否開放辣度）。
- 新增全店共用 `AddOn` 清單（名稱、加價，加價須 `decimal` 且 > 0、停用開關），維護介面**附屬於「菜單管理」頁面**，以頁籤切換「品項｜加料」，不另開獨立選單入口。
- 加料比照現行 `MenuItem` 規則：已被歷史訂單使用過者禁止硬刪除，僅能停用。
- 加料清單於維護頁面/點餐選擇清單超過 6 項時，清單區塊可捲動（`overflow-y: auto`），不做搜尋框。

### 2.2 客製化點餐（Order 模組擴充）

**使用者故事**

- As a 店長, I want 點選有加料/辣度設定的品項時，看到客製化表單（辣度單選、加料多選＋各自數量、備註）, so that 可以正確記錄顧客需求並自動計價。
- As a 店長, I want 沒有客製化設定的品項維持原本的簡易表單（數量＋備註）, so that 大部分品項的點餐速度不受影響。

**驗收標準**

- 品項客製化判斷：`SupportsAddOns` 或 `SupportsSpiceLevel` 任一為真，即視為客製化品項，點擊後開啟客製化表單；兩者皆否則維持現行簡易表單。
- 客製化表單欄位：
  - 辣度（單選，僅 `SupportsSpiceLevel` 品項顯示）：~~**不辣／微辣／小辣／中辣／大辣**，五級固定選項；預設值為微辣~~ → **2026-10-05 修訂：改為數字 0～6（0 為不辣），畫面與出單皆只顯示數字，預設 1**，不開放自訂。有特殊需求（例如「大辣加倍」）由備註欄位補充，不擴充辣度選項本身。
  - 加料（可複選，僅 `SupportsAddOns` 品項顯示）：勾選後才展開該加料的數量調整（＋／－），未勾選僅佔一行，避免表單過長；可複選多種加料，各自指定數量。
  - 備註：選填，自由文字，沿用現行欄位與長度限制。
  - **數量欄位不顯示，固定為 1**：客製化品項每筆 `OrderItem` 恆為 1 份，若需多份相同或不同客製化組合，需重複點擊「加點」個別新增；此規則避免「多份是否都套用同一客製化」的計價與出單歧義。
  - 表單即時顯示小計（單價 ＋ 已選加料加總），送出前可核對金額。
- 簡易表單（無客製化品項）維持現行「數量＋備註」欄位與互動，不受影響。
- 錯誤處理：
  - 訂單已鎖定（非 `Open`）→ 沿用現行錯誤提示，導回訂單詳情頁。
  - 品項已下架 → 沿用現行錯誤提示。
  - 送出時選到的加料已被停用 → 擋下並提示「部分加料已下架，請重新選擇」，不寫入資料庫。

### 2.3 計價規則

- `OrderItem` 小計 = `UnitPrice`（品項單價快照）＋ Σ(`OrderItemAddOn.UnitPrice` × `OrderItemAddOn.Quantity`)（加料單價快照 × 數量）。因客製化品項 `Quantity` 恆為 1，公式不需再乘一次品項數量。
- 加料價格於下單當下寫入快照（比照現行 `OrderItem.UnitPrice` 的做法），避免日後加料調價影響歷史訂單金額。
- 訂單 `TotalAmount` 加總邏輯延續現行「每次異動即重新加總所有品項小計」的做法，一併涵蓋加料金額。

### 2.4 出單列印格式（連動 [v3.md](v3.md)）

- 出單聯／加點單／全單在品項名稱下方，額外列出該品項的辣度（若有）與加料清單（名稱＋數量），例如：
  ```
  雞排飯 x1                $130
    辣度：2
    加料：加蛋 x1 (+$10)
  ```
- ~~作廢通知單同樣列出辣度／加料（維持現行「不含金額」規則）。~~（2026-09-30 已取消作廢通知列印，見 v3.md）
- 無客製化的品項維持現行列印格式，不受影響。

### 2.5 營收報表

- 本次**不**拆分「加料銷售額」統計維度，加料金額已內含於品項小計與訂單總額，[mvp.md](mvp.md) 2.4 節既有報表邏輯無需修改即可正確反映總額。

## 3. 明確排除（本次不做）

- 加料清單不分類別／分組（不分葷素、醬料等），統一顯示。
- 不支援「品項專屬加料」（即不同品項各自綁定不同加料清單），全店僅一份共用清單。
- 辣度選項不開放自訂新增/修改，固定為 0～6（2026-10-05 起）。
- 客製化品項的點餐表單不提供數量欄位；多份需求以重複加點多行表達。
- 報表不拆分加料銷售額統計。

## 4. 已識別風險與因應

| 風險 | 因應 |
| --- | --- |
| 客製化品項強制數量為 1，多份需重複操作，可能增加點餐步驟 | 現場多為單店手動點餐，此規則換取計價/出單零歧義，風險可接受 |
| 全店共用加料清單無法限定「僅特定品項可選特定加料」 | 已於需求訪談中確認接受此限制（Option B），換取維護與開發成本降低 |
| 加料清單項目增多時，點餐/維護頁面表單變長 | 加料清單採可捲動區塊（超過 6 項捲動），未做搜尋，未來項目大量增加需再評估 |
