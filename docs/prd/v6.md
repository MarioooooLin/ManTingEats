# PRD — ManTingEats v6（結帳收款與找零）

> 狀態：**已定案**（2026-10-04）。本文件修改 [mvp.md](mvp.md) 中「結帳只顯示應收總金額，不做找零計算」的範圍。

## 1. 需求摘要

**目標**：結帳時記下顧客給了多少錢，系統自動算出找零，減少店長心算出錯。

**使用者情境**：店長單人作業、僅收現金。多數顧客會給剛好或整數鈔票，操作需盡量少按幾下。

## 2. 結帳流程

1. 訂單詳情頁按「結帳（應收 $X）」→ 跳出**結帳視窗**（不直接結帳）。
2. 結帳視窗中，店長**必須擇一**完成收款才能結帳：

   | 方式 | 操作 | 結果 |
   | --- | --- | --- |
   | **收剛好** | 按「收剛好」 | 直接結帳，不需輸入 |
   | **快速金額** | 按金額按鈕（見下方） | 帶入收款金額，顯示找零，再按「確認結帳」 |
   | **手動輸入** | 用數字鍵盤輸入收款金額 | 即時顯示找零，再按「確認結帳」 |

3. 收款金額**小於應收**時，「確認結帳」按鈕停用，並顯示「還差 $N」。
4. 結帳完成後，訂單頁上方的成功訊息顯示「結帳完成，收 $X，找零 $Y」，方便店長找錢時再看一次。

### 2.1 快速金額按鈕

- 依應收金額顯示**大於應收**的常用面額：下一個整百、$500、$1000（重複或小於應收者不顯示）。
  - 例：應收 $285 → 顯示「$300」「$500」「$1000」。
  - 例：應收 $650 → 顯示「$700」「$1000」。
- 按下後可再手動修改輸入框的金額。

## 3. 資料與驗證

- 收款金額與找零**只在畫面上計算，不存進資料庫**（使用者決議），不需新增 Migration。
- 收款金額須為整數、介於應收金額與 $100,000 之間。
- 後端 `Checkout` 仍會收到收款金額並檢查不得小於應收，防止繞過畫面直接送出；檢查後即丟棄，不寫入資料庫。
- 若結帳前仍有「待出單」品項，沿用 v5 規則擋下結帳（結帳按鈕停用，不會跳出結帳視窗）。

## 4. 明確排除（本次不做）

- 不做刷卡、行動支付等其他付款方式。
- 不做收款紀錄、現金對帳、每日收銀報表（收款金額未存檔）。
- 不做發票、收據列印。
