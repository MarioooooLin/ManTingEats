# PRD — ManTingEats v17（店長自行管理菜單分類）

> 狀態：**已定案**（2026-10-24，使用者決議：只停用不刪除、停用時有上架品項就擋下、上移／下移排序、保留原三個分類；2026-10-25 追加：分類、品項、加料下架／停用的收到列表最下方的收合區塊）。取代 2026-09-22 起「菜單分類固定為吃／喝／其他」的做法（`ChangeMenuItemCategoryToEnum` Migration，原本未寫入 PRD）；支出分類（[v2.md](v2.md)）維持固定清單，不在本次範圍；品項、加料、點餐、出單規則不變。

## 1. 需求摘要

**背景**：菜單分類寫死在程式裡（`MenuCategory` 列舉：吃、喝、其他），要新增或改名都得改程式、重新部署。

**目標**：店長在「菜單管理」自行新增、改名、排序、停用分類；下架／停用的分類、品項、加料收到列表最下方，列表只看到在用的。

## 2. 規則

### 2.1 分類管理（菜單管理頁的「分類」分頁）

- **新增**：輸入名稱（最多 20 字），新分類排在最後。
- **改名**：點餐頁分頁與此分類下的品項一併更新。
- **名稱不可重複**（含已停用的分類）：名稱就是點餐頁的分頁標籤，重複會分不出來。名稱前後空白自動去除。
- **排序**：啟用中的分類每列有「上移」「下移」，第一列不能上移、最後一列不能下移。順序即點餐頁分類分頁的順序。
  - 只在啟用中的分類之間交換（跳過停用分類）；停用分類不顯示上移／下移，維持原位，重新啟用後回到原本位置。
- **只能停用、不能刪除**：與品項、加料一致，品項一定有分類。
  - **還有上架品項時不能停用**，提示「分類「X」還有 N 個上架品項，請先將品項移到其他分類或下架，再停用分類」，避免品項無聲無息從點餐頁消失。
  - 已下架的品項可留在停用的分類中；之後啟用分類即可再上架。
- 列表顯示每個分類的上架品項數（另註明已下架數），讓店長知道停用前要先處理哪些品項。

### 2.2 品項與分類

- 新增品項：分類下拉只列**啟用中**的分類；沒有任何啟用中分類時提示先新增分類。
- 編輯品項：下拉列啟用中的分類，另含品項**目前的分類**（即使已停用，標示「已停用」），改價格等其他欄位時不會被迫換分類；不能改到其他已停用的分類。
- 上架品項：所屬分類已停用時擋下，提示先啟用分類或改到其他分類。否則可繞過「停用前須先下架」。
- 因此**上架品項的分類一定是啟用中**。

### 2.3 下架／停用的收合區塊（品項、加料、分類三個分頁）

- 每個分頁上方只列上架（啟用）中的資料；下架（停用）的收在最下方的收合區塊「已下架品項（N）」「已下架加料（N）」「已停用分類（N）」，N 為數量。
- 每次進頁面都預設收起；點標題展開，可編輯、重新上架（啟用）。上架後該筆回到上方列表，並顯示「已上架」提示。
- 沒有下架資料時不顯示收合區塊。
- **不提供刪除**（2026-10-25 使用者決議）：訂單明細只記品項 Id、未另存名稱，營收報表品項排行與補印都讀品項名稱，刪除賣過的品項會讓歷史資料出錯；資料量（品項、分類最多數百筆）對資料庫不是負擔，困擾的是列表雜亂，以收合解決。
- 用詞維持：品項、加料為「上架／下架」，分類為「啟用／停用」。

### 2.4 點餐頁

- 分類分頁依店長設定的順序排列；只顯示有上架品項的分類（沒有品項的分類不顯示分頁，與原本相同）。

## 3. 影響範圍

| 位置 | 變更 |
| --- | --- |
| 資料庫 | 新增 `MenuCategories` 表；`MenuItems.Category`（列舉值）改為 `CategoryId`（外鍵，禁止連動刪除） |
| 菜單管理頁 | 新增「分類」分頁；品項列表依分類順序排列、顯示分類名稱；三個分頁的下架／停用資料收到最下方收合區塊 |
| 新增／編輯品項 | 分類下拉改由資料庫讀取 |
| 點餐頁 | 分類分頁依設定順序、顯示分類名稱 |
| 後端 | `MenuController` 新增分類的新增、編輯、停用／啟用、上移／下移；移除 `MenuCategory` 列舉 |

**不變**：出單內容、報表、日結（皆未使用分類）；品項名稱不可重複的規則。

## 4. 資料

- Migration `AddMenuCategory`：建立 `MenuCategories`，寫入原本的三個分類（Id 1 吃、2 喝、3 其他，依此順序），再把品項的列舉值（0／1／2）換成對應的分類 Id，最後加外鍵。正式環境既有品項的分類不變。
- 還原（Down）時只能對應回三個初始分類，之後新增的分類一律歸為「其他」。
- 開發用測試菜單 `scripts/dev-data/menu-seed.sql` 同步改為新結構。

## 5. 驗收標準

- 可新增分類，新分類出現在列表最後，並可在新增／編輯品項時選用。
- 可改名，點餐頁分頁名稱跟著改。
- 名稱重複（含已停用）時擋下並提示。
- 上移／下移後，點餐頁分類分頁順序跟著變。
- 有上架品項的分類無法停用並提示原因；只剩下架品項時可停用、可再啟用。
- 品項、加料、分類分頁上方只列上架（啟用）中的；下架的在最下方收合區塊，預設收起、顯示數量，展開後可編輯、上架。
- 上移／下移會越過停用分類；停用分類沒有上移／下移按鈕。
- 停用分類中的品項無法上架；新增品項不能選停用的分類。
- 部署後既有品項維持原本的分類（吃／喝／其他），點餐頁分頁順序與部署前相同。
