# PRD — ManTingEats v3（出單列印模組）

> 狀態：已定案（2026-09-22）。**2026-10-04 起連線方式、結帳補印與失敗處理由 [v5.md](v5.md) 取代**（改為 iPad + PassPRNT），本文件保留作為歷史紀錄。本文件為 mvp.md 的擴充版本，新增「出單列印」功能，不修改既有模組範圍。

## 1. 需求摘要

**目標**：點餐/加點時自動列印出單聯，取代店員口頭喊單或手寫紙條傳遞的方式；因目前為單人作業（兼點餐/出餐/收銀），此單同時兼作結帳金額參考。

**使用者情境**：店內收銀/點餐處放置一台網路熱感印表機（Star Micronics mC-Print3，型號 MCP31L），供廚房出餐與老闆結帳雙重用途。

## 2. 模組詳細規格

### 2.1 連線方式

- 採用**網路熱感印表機**，透過 LAN 直連，IP + Port 設定。
- 印表機型號：Star Micronics mC-Print3（MCP31L），LAN 介面。實作改採 **raw TCP socket 直連 IP:9100**（印表機自我測試頁確認 `TCP#9100: ENABLE`），不依賴 Star 官方 SDK，優點是跨平台（Windows 開發機/Linux Docker 容器都可用）且不需額外原生依賴。
- 印表機字元模式為 **T-Chinese(Big5)**，程式送出的列印內容需將中文字串由 UTF-8 轉換為 **Big5 編碼**，否則中文品項名稱會亂碼。
- 印表機 IP/Port 為環境設定，存於 `appsettings.json`（比照現有 DB 連線字串慣例），不做資料庫可視化設定介面。

### 2.2 觸發時機與內容

為避免每次加點即時列印造成零碎亂印，**不在加點當下自動列印**，改為明確的「確認出單」動作，一次批次列印自上次確認後新增的所有品項：

| 動作 | 觸發列印 | 內容範圍 |
| --- | --- | --- |
| 加點（新增品項） | 不列印，僅寫入資料庫並標記為「待出單」 | — |
| 確認出單（手動按鈕，批次列印自上次確認後的所有待出單品項） | 若訂單尚無任何已出單品項，印「全單」；否則印「加點單」 | 本次確認的所有待出單品項（名稱、數量、單價、小計）、桌號、備註、時間、**訂單目前總金額** |
| 結帳 | 若仍有待出單品項，結帳前自動補列印一次（安全網，避免忘記按「確認出單」導致廚房漏單） | 同上 |
| 作廢訂單 | **不列印**（2026-09-30 使用者決議：店長直接在原出單紙本上手動打叉即可） | — |

- 介面上每項品項會顯示「待出單」/「已出單」狀態 badge，方便店長確認哪些還沒送到廚房。
- 出單聯不含顧客收據格式（例如統編、稅額），僅供店內內部使用。

### 2.3 失敗處理

- 印表機離線/連線失敗時，**不阻擋**建單/加點/作廢操作，訂單照常寫入資料庫。
- 畫面顯示警告訊息（例如「出單失敗，請確認印表機並手動補印」）。
- 提供「補印」按鈕，可針對單一訂單重新觸發列印（含全單/最近一次加點）。
- 列印失敗需記錄簡易日誌（時間、訂單編號、失敗原因），供排查用，不做正式稽核紀錄。

## 3. 明確排除（本次不做）

- 不做多台印表機分流（例如飲料吧/廚房分開出單）。
- 不做出單聯樣式自訂設定介面（版面固定寫死）。
- 不做正式顧客收據格式（統編、稅額等）。
- 不做列印佇列/離線快取重送機制（僅提供手動補印）。
- 不列印作廢通知（2026-09-30 移除原規劃，改由店長在原出單上手動打叉）。

## 4. 已識別風險與因應

| 風險 | 因應 |
| --- | --- |
| 印表機離線導致廚房漏單 | 畫面明顯警告 + 手動補印按鈕，仰賴店員即時發現 |
| 中文內容編碼錯誤導致亂碼 | 列印前統一將字串轉換為 Big5 編碼，開發時需針對中文品項名稱實機驗證 |
| 加點單與全單格式混淆 | 加點單強制標示「加點」字樣、且僅列新增品項 |
| 出單含金額，未來若擴編請服務生，等同服務生也能看到金額 | 現階段單人作業可接受；若未來真的擴編，屆時再評估是否拆分為兩張單（無金額廚房單 + 含金額結帳單） |

## 5. 技術確認紀錄

- 已透過印表機自我測試頁（開機按住送紙鍵）確認：LAN 功能正常（`ASB(LAN)`/`NSB(LAN)`: Valid）、字元模式為 `T-Chinese(Big5)`；測試當下尚未取得網路 IP（DHCP 未配發），待實際接上網路後續測連線。
- 指令串接方式實作改用 raw TCP socket 直連 IP:9100（不依賴 Star 官方 SDK），以支援 Linux Docker 容器部署環境。
- 出單觸發機制實作改為明確「確認出單」手動批次列印（非加點當下自動列印），避免零碎亂印；結帳前自動補列印仍待出單的品項作為安全網。
