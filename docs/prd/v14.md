# PRD — ManTingEats v14（整批點餐）

> 狀態：**已定案**（2026-10-13，使用者依店長回饋決議）。本文件取代 [v4.md](v4.md)、[v10.md](v10.md) 中「每次加點一個品項、送出後重新載入頁面」的點法；品項、加料、金額規則不變。

## 1. 需求摘要

**背景**：原本每點一個品項都要按「加點」送出，頁面重新載入後分類分頁跳回第一個、畫面回到最上方，點下一項要重新選分類，點一桌多樣品項很費時。

**目標**：先把品項放進畫面上的「本次點餐」清單，選完後**一次送出**。

## 2. 規則

### 2.1 點餐清單（只存在瀏覽器，送出前不寫入資料庫）

- **一般品項**（不可加料、不可選辣度）：點卡片 = 清單中該品項 +1，不跳面板。卡片上顯示目前份數，並有 −／+ 可調整；減到 0 即從清單移除。備註在清單中填寫。
- **客製化品項**：點卡片跳出原本的份數／辣度／加料／備註面板，按「加入清單」放進清單。份數、辣度、加料、備註完全相同時合併成一列（份數相加），否則另起一列。卡片上顯示該品項在清單中的總份數。
- 清單每列可調整份數（1～99）、刪除；顯示小計，底部顯示本次合計。
- 清單尚未送出就要離開或重新整理頁面時，瀏覽器跳出提醒。

### 2.2 送出

- 「送出並出單 N 項」一次寫入所有品項（狀態為「待出單」），**接著自動出單**：導回訂單頁後自動執行原本的「確認訂單」，開啟 PassPRNT；出單成功與失敗的處理沿用 v5。
  - 不在送出後直接回傳出單頁：該頁若重新整理，瀏覽器會重送點餐表單而重複點餐。自動出單標記讀一次即消失，重新整理訂單頁也不會再出一次。
  - 「確認訂單」按鈕保留，僅在有待出單品項時出現，用於出單失敗後重新出單，或在 iPad 印手機點的單。
- **手機點餐不出單**（2026-10-13 使用者決議）：印表機只接在 iPad，手機送出後只寫入品項，提示「請到 iPad 按『確認訂單』出單」；手機上不顯示「確認訂單」按鈕，改顯示同樣提示。
  - 以 User-Agent 判斷：iPhone／iPod、含 Mobile 的 Android 為手機。iPadOS Safari 以 Mac 桌機身分送出，不會被判為手機；Mac 電腦亦視為可出單裝置（店內不使用）。
- **訂單列表標示待出單**：未結帳訂單有待出單品項時，狀態旁顯示「待出單 N 項」，讓 iPad 看出哪張單要出單。
- **全部成功或全部不寫入**：任一品項下架、加料停用、數量不合法時，整批退回並顯示原因，清單需重新選擇。
- **待出單上限 20 項**：「尚未出單的品項 + 本次清單」超過 20 項（以「列」計，滷肉飯 x5 算 1 項）時不能送出，提示分批送出（有待出單品項時先在 iPad 出單）。已出單的品項不計，大桌可分批出單。
  - 原因：出單內容放在網址中交給 PassPRNT，過長可能列印失敗；確切上限未實測，20 為使用者決議的暫定值（`OrderLimits.MaxPendingItems`），日後大單實測後可調整。

## 3. 影響範圍

| 位置 | 變更 |
| --- | --- |
| 訂單詳情頁點餐區 | 卡片點選行為、本次點餐清單、送出按鈕；移除一般品項的數量面板 |
| 訂單詳情頁出單區 | 送出後自動出單；手機改顯示「請到 iPad 出單」提示 |
| 訂單列表 | 狀態旁顯示「待出單 N 項」 |
| 後端 | 新增 `AddItems`（整批加點），取代單筆 `AddItem`；`PrintDevice.IsPhone` 判斷手機 |

**不變**：品項／加料金額計算、出單內容與回寫流程、補印、結帳、移除品項、作廢、報表。

## 4. 資料

- 不需 Migration。

## 5. 驗收標準

- 可連續點多個分類的品項，過程中頁面不重新載入、分類分頁不會跳回。
- 送出後各品項、辣度、加料、備註、金額與逐項加點的結果相同。
- 任一品項不合法時整批不寫入。
- iPad 送出後直接開啟 PassPRNT 出單，不需再按「確認訂單」；重新整理訂單頁不會重複出單或重複點餐。
- 手機送出後不開 PassPRNT，顯示「請到 iPad 出單」；手機上看不到「確認訂單」。
- 訂單列表可看出哪些未結帳訂單有待出單品項。
- 待出單 + 本次清單超過 20 項時，畫面與後端都擋下。
- 清單有內容時離開頁面會跳出提醒；送出時不會。
