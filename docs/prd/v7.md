# PRD — ManTingEats v7（帳號與權限管理）

> 狀態：**已定案**（2026-10-07）。

## 1. 需求摘要

**目標**：目前只有部署時以 `.env` 建立的一組店長帳號，所有登入者都能使用全部功能，也無法改密碼。新增員工帳號與權限區分，讓員工只能操作日常營業所需的功能，並讓店長能更換初始密碼。

**角色**：系統只有**一個店長**（部署時由 `.env` 的 `SEED_ADMIN_*` 建立的帳號），其餘皆為**員工**。不能新增其他店長。

## 2. 權限

| 功能 | 店長 | 員工 |
| --- | :---: | :---: |
| 訂單（開單、點餐、出單、補印、結帳、取消、作廢） | ✅ | ✅ |
| 訂位記錄（新增、查詢、編輯、刪除） | ✅ | ✅ |
| 菜單管理（品項、加料） | ✅ | ❌ |
| 支出記錄 | ✅ | ❌ |
| 營收報表 | ✅ | ❌ |
| 帳號管理 | ✅ | ❌ |

- 員工**可以**作廢已結帳的訂單（使用者決議），系統照常記錄作廢原因與操作者。
- 員工看不到無權限功能的導覽列連結與首頁卡片；直接輸入網址會看到「沒有權限」頁面。
- 權限以後端檢查為準（`[Authorize(Roles = "Manager")]`），隱藏連結只是介面上的便利。

## 3. 帳號管理（僅店長）

導覽列新增「帳號管理」，頁面列出所有帳號（帳號、角色、狀態、建立時間）。

| 動作 | 說明 |
| --- | --- |
| 新增員工 | 輸入帳號與初始密碼；角色固定為員工 |
| 重設員工密碼 | 店長直接設定新密碼，不需知道舊密碼 |
| 停用／啟用員工 | 停用後無法登入；**不提供刪除**（歷史訂單記錄了開單與作廢的操作者，刪除會使紀錄失去對象） |
| 變更自己的密碼 | 店長須輸入目前密碼，再設定新密碼 |

- **只有店長能設定密碼**（使用者決議）：員工不能自行改密碼，忘記密碼時由店長重設。
- 店長帳號不能被停用（系統只有一個店長，停用會讓所有人都無法管理帳號）。
- 帳號名稱：3～50 字，不可與既有帳號重複（不分大小寫），建立後不可修改。
- 密碼：至少 8 碼、最多 100 碼。
- 停用員工、或重設某人密碼後，該帳號**已登入的裝置會立即被登出**（每次請求比對帳號的安全戳記），避免離職員工在 iPad 上保持登入。
- 停用的帳號輸入正確密碼時顯示「此帳號已停用，請洽店長」；密碼錯誤時維持「帳號或密碼錯誤」，不透露帳號狀態。

## 4. 資料與部署

- `Employee` 新增 `IsActive`（是否啟用）與 `SecurityStamp`（安全戳記，密碼變更或停用時更新）兩個欄位，需要 Migration；既有帳號預設為啟用。
- 既有的店長帳號、密碼維持不變；但部署前發出的登入 Cookie 沒有安全戳記，**部署後所有裝置需重新登入一次**。
- 啟動時建立店長帳號的邏輯不變（只在資料庫完全沒有帳號時，依 `.env` 建立）。
- **上線後請店長立即用「變更自己的密碼」更換初始密碼**（初始密碼目前寫在 VPS 的 `.env` 中）。

## 5. 明確排除（本次不做）

- 不做多個店長、不做自訂角色或逐項權限設定。
- 不做員工自行改密碼、忘記密碼信件。
- 不做帳號刪除、不做帳號改名。
- 不做登入紀錄、操作稽核報表（作廢原因與操作者沿用既有紀錄）。
