# PRD — ManTingEats v5（出單列印改為 iPad + PassPRNT）

> 狀態：**已定案**（2026-10-04）。本文件**取代** [v3.md](v3.md) 的連線方式、結帳補印與失敗處理；v3 中「確認出單批次列印」「全單／加點單區分」「作廢不列印」等決議沿用。

## 1. 需求摘要

**目標**：主機將放在雲端，店內無法拉網路線讓印表機上網，原本「伺服器以 TCP 9100 直連印表機」的方式不適用。改由店內 iPad 以 USB 連接印表機，網頁透過 Star **PassPRNT** App 列印出單。

**使用者情境**：店長單人作業，於 iPad 上點餐、按「確認訂單」出單；出單聯同時供廚房製作與結帳金額參考。

## 2. 硬體與連線

- 印表機：Star mC-Print3 **MCP31L**，以 USB 線接 iPad（印表機 USB-A 2.4A 孔，同時為 iPad 充電）。
- 紙張：**58mm 熱感紙**。印表機本身與 PassPRNT App 的紙寬設定均須為 58mm。
- 列印方式：網頁導向 PassPRNT URL scheme：

  ```
  starpassprnt://v1/print/nopreview?back=<回呼網址>&html=<出單 HTML>&size=2&cut=partial&popup=enable
  ```

  | 參數 | 值 | 說明 |
  | --- | --- | --- |
  | `size` | `2` | 2 吋（58mm）。設成 `3` 會依 80mm 排版，右側被裁切（2026-10-04 實測） |
  | `cut` | `partial` | 印完自動半切（實測可用） |
  | `popup` | `enable` | 錯誤時由 PassPRNT 跳出訊息 |
  | `back` | 回呼網址 | 印完回到此網址並附上 `passprnt_code`（`0` = 成功）與 `passprnt_message` |

- PassPRNT 將 HTML 轉成圖片列印，中文由 iPad 字型處理，**不再需要 Big5 編碼**。
- **只有安裝 PassPRNT 並接著印表機的 iPad 能出單**；其他裝置按出單會無法開啟 PassPRNT。

### 已知限制（實測結果）

- Safari 每次列印都會跳出「是否在 PassPRNT 中打開」確認視窗，需多按一次「打開」；此為 iOS 安全機制，網頁端無法關閉。「加入主畫面」模式下是否仍會跳出待實測。
- 印完回到**同一分頁**（實測確認），可直接在原頁面處理列印結果。

## 3. 出單觸發時機與內容

| 動作 | 是否列印 | 內容 |
| --- | --- | --- |
| 加點（新增品項） | 不列印，標記為「待出單」 | — |
| 確認訂單（手動按鈕） | 若訂單尚無已出單品項 → 印「**全單**」；否則 → 印「**加點單**」 | 全單：所有品項；加點單：僅本次待出單品項。兩者底部皆印**訂單目前總金額**（含先前已出單品項，隨加點累加） |
| 結帳 | **不列印**（v3 的結帳前自動補印移除） | — |
| 補印（手動按鈕） | 印「**補印**」全單 | 訂單所有品項與目前總金額；不改變任何品項的出單狀態 |
| 作廢訂單 | 不列印（沿用 2026-09-30 決議） | — |

**決策原因（結帳不補印）**：使用者表示出單以每次點餐的「確認訂單」為準，結帳時不需再印；加點單底部的總金額會隨加點累加，最後一張出單即為結帳金額參考。

## 4. 出單版面（58mm，已實測確認）

以 2026-10-04 實測版本為準（`wwwroot/dev/passprnt-test.html` 的 `ticketHtml`）：

| 區塊 | 字級 | 備註 |
| --- | --- | --- |
| 標題（全　單／加　點／補　印） | 36px 粗體 | 上下粗框線 |
| 訂單編號、桌號 | 32px 粗體 | 靠右 |
| 通路、時間 | 22px | 靠右 |
| 品名／數量 | **36px 粗體** | 數量固定靠右，品名過長於左欄換行 |
| 辣度／加料／備註 | **30px** | 內縮於品名下方 |
| 總金額 | 26px | 標籤：全單「總金額」、加點單「訂單目前總金額」 |

- 整張 `word-break: break-all`，任何長字串都換行而非被裁切。
- 出單 HTML 由伺服器以 Razor partial 產生（版面集中一處維護），前端只負責組 PassPRNT 網址。

## 5. 確認訂單流程與失敗處理

### 5.1 正常流程

1. 店長在訂單詳情頁按「確認訂單（N 項）」。
2. 伺服器產生出單 HTML，並記下**本次要出單的品項 ID**（避免列印期間有人加點，回來時把沒印到的品項也誤標為已出單）。
3. 頁面導向 PassPRNT → Safari 確認視窗按「打開」→ 印表機出單、自動切紙。
4. PassPRNT 回到訂單詳情頁並帶回 `passprnt_code`：
   - `0`（成功）→ 將步驟 2 記下的品項標記為「已出單」，顯示「已出單」。
   - 非 `0`（失敗）→ 品項維持「待出單」，顯示警告與 PassPRNT 的錯誤訊息。
5. 回呼網址為 GET；標記已出單的動作由頁面以 POST（含 Anti-Forgery Token）送出，不在 GET 中直接改資料。

### 5.2 失敗處理

- 常見原因：沒紙、印表機沒開、USB 沒接好。
- 只要不是成功（`passprnt_code` 非 `0`、或沒有回呼），品項一律維持「待出單」，店長處理好印表機後**再按一次「確認訂單」**即可重印同一批品項。
- 若在 Safari 確認視窗按「取消」，不會有回呼，品項同樣維持「待出單」。
- 列印結果（成功／失敗代碼與訊息）寫入應用程式日誌，供排查，不做正式稽核紀錄。

## 6. 定案決議（2026-10-04 使用者確認）

1. **列印失敗一律人工重印**：只要 PassPRNT 未回報成功（缺紙、沒開機、按取消等），品項一律維持「待出單」，由店長處理後再按「確認訂單」。不提供「已印出，手動標記」按鈕；若印表機在換紙後自行補印，可能出現重複出單，由店長自行忽略。
2. **結帳前擋下待出單品項**：訂單仍有「待出單」品項時不允許結帳，提示「尚有 N 項未出單，請先確認訂單或取消這些品項」。
3. **品項行不印單價／小計**：只印品名、數量與客製化內容，底部印總金額。
4. **移除舊的 `LanReceiptPrinterService`**（TCP 9100 + Big5）與 `Printer` 設定區塊，需要時可從 git 歷史找回。

## 7. 明確排除（本次不做）

- 不做多台印表機分流、不做多台 iPad 出單。
- 不做列印佇列／離線重送（失敗時人工再按一次）。
- 不做 Star CloudPRNT（需讓印表機上網、額外硬體，保留為未來多裝置出單的選項）。
- 不做出單樣式自訂介面（版面固定）。

## 8. 已識別風險與因應

| 風險 | 因應 |
| --- | --- |
| 出單 HTML 放在網址中，品項很多時網址過長導致 PassPRNT 無法處理 | 實作後以 15 項以上的大單實測；必要時精簡 HTML（移除多餘樣式） |
| 在非出單 iPad 上按「確認訂單」 | PassPRNT 開不起來、無回呼，品項維持「待出單」，不會誤標 |
| 列印期間有人加點 | 回呼時只標記送印當下記錄的品項 ID |
| PassPRNT App 更新改變行為 | 保留 `wwwroot/dev/passprnt-test.html` 供日後快速重測 |
