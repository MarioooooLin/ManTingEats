# PRD — ManTingEats v18（日結與營收報表加入外送營收）

> 狀態：**已定案**（2026-11-06）。擴充 [v13.md](v13.md) 日結與營收報表；現金對帳公式不變。

## 1. 需求摘要

**背景**：店家同時接 Uber Eats、foodpanda。外送單在各平台自己的接單 App 處理（不串 API，見 MEMORY 2026-10-23），金流不經過本系統。日結與營收報表只算店內（內用／外帶），打烊時要另外打開兩個平台後台手算合計，整合困難。

**目標**：日結時一併記錄兩個外送平台的當日數字，日結與營收報表直接看到三個管道的合計。

## 2. 規則

### 日結（店長、員工皆可填）

- 日結表單新增「外送平台」區塊，Uber Eats、foodpanda 各填：
  - **訂單數**
  - **營業額**：顧客付的金額
  - **實收**：平台扣抽成與各項費用後撥給店家的金額
- 數字照各平台商家後台當日資料**手動抄寫**；系統不以抽成 % 估算（實際費用含活動補貼、行銷費等，固定比例會有誤差）。
- 整個平台可留空，視為 0（當天沒開外送或沒單）；不可為負數，金額需為整數。
- **同一平台只要填了任何一格，訂單數、營業額、實收三格都要填**才能日結（沒單填 0）：留空會當成 0，只填一部分會讓總營業額或淨利少算，系統也分不出是 0 還是忘了填。
- **應有現金公式不變**（`零用金 + 店內營收 − 支出`）：外送款不進收銀機。
- 畫面即時顯示：店內營收、外送營業額、總營業額、外送實收。
- 重新日結時沿用上次填的外送數字，只需修正有錯的欄位；外送數字與其他欄位一樣存成快照，以最後一次日結為準。
- 日結明細顯示兩平台的訂單數、營業額、實收與總營業額；日結紀錄列表新增「外送營業額」欄。

### 營收報表（僅店長）

- 外送數字取區間內**每個營業日最後一次日結**的值加總。
- 新增「總營業額」= 店內營收 ＋ 外送營業額。
- 原「總營收」改稱「店內營收」，算法不變（品項＋加料排行 − 折扣 = 店內營收）。
- **淨利 = 店內營收 ＋ 外送實收 − 支出**（外送以實際入帳計算）。
- 通路拆分表顯示內用、外帶、Uber Eats、foodpanda 的訂單數、營業額、實收（店內通路營業額即實收）。
- 區間內（不含未來日期）有營業日尚未日結時，顯示「N 個營業日尚未日結，外送未計入」提示。

## 3. 已知限制

- 外送只有每日總額，沒有品項資料，不列入品項／加料排行。
- 未日結的營業日沒有外送數字；補做日結後報表即會納入。
- 平台撥款通常每週一次，系統不核對實際撥款金額。
- 平台若增加或更換（例如 foodpanda 出售後改名），需修改程式與 Migration。
