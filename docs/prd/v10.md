# PRD — ManTingEats v10（客製化品項可點多份）

> 狀態：**已定案**（2026-10-08，使用者決議加料數量為「每份」的量）。本文件取代 [v4.md](v4.md) 中「客製化品項數量固定為 1」及小計公式的規則。

## 1. 需求摘要

**背景**：可加料或可調辣度的品項（客製化品項）原本每次加點固定 1 份，點 3 份相同設定的品項要加點 3 次，點餐費時。

**目標**：客製化品項也能一次選擇份數；選好的辣度、加料、備註**套用到每一份**，存成同一行。各份設定不同時，由店員分開加點。

## 2. 規則

- 客製化面板新增「份數」（1～99，與一般品項相同）。
- **加料數量為每份的量**：麻辣鍋 x3、加料「蛋 x2」= 3 份各加 2 顆，共 6 顆。
- 金額：

  ```
  整行小計 =（品項單價 + 每份加料金額）x 份數
  每份加料金額 = Σ（加料單價 x 加料數量）
  ```

  例：$90 品項 x3、蛋（$10）x2 → (90 + 20) x 3 = $330。

## 3. 影響範圍

| 位置 | 呈現 |
| --- | --- |
| 點餐面板 | 份數選擇；小計即時顯示（品項 + 加料）x 份數 |
| 訂單品項清單 | 小計含加料 x 份數；份數 > 1 時加料標示「加料（每份）」 |
| 出單 | 品項印總價（單價 x 份數）；份數 > 1 時印「加料（每份）：蛋 x2」，右側印整行加料總價（每份加料金額 x 份數） |
| 營收報表 | 加料排行的數量與金額皆乘以品項份數（上例計為蛋 6 顆、$60） |

**不變**：一般品項的點法、單品項移除、出單／結帳流程、折扣。

## 4. 資料

- 不需 Migration：`OrderItemAddOn.Quantity` 改為代表「每份」的量。v10 之前客製化品項份數皆為 1，「每份」與「整行合計」數值相同，既有資料不需轉換。
- 加料數量存每份的量、不在存檔時預先乘以份數，讓畫面、出單與資料庫的數字一致（廚房看到的就是每份要加多少）。

## 5. 驗收標準

- 客製化品項可選 1～99 份，送出後存成一行，辣度／加料／備註正確。
- 訂單總額、畫面小計、出單金額、報表加料排行皆以「每份加料 x 份數」計算。
- 報表中品項排行 + 加料排行 − 折扣總額 = 總營收。
