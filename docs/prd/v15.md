# PRD — ManTingEats v15（未成立訂單取消即刪除）

> 狀態：**已定案**（2026-10-13，使用者依店長回饋決議）。補充 [mvp.md](mvp.md) 訂單狀態機：「已作廢」只用於已成立的訂單。

## 1. 需求摘要

**背景**：從未出單的訂單（誤觸建單、測試）按「取消」後，原本會變成「已作廢」，保留單號並出現在訂單列表與日結的作廢張數中。店長認為訂單沒有成立，不該算作廢。

**目標**：區分「取消」與「作廢」：

| | 取消 | 作廢 |
| --- | --- | --- |
| 適用 | **未成立**：從未有任何品項出單成功 | **已成立**：至少一個品項出單成功過（含已結帳） |
| 結果 | 整張訂單（含品項、加料）從資料庫刪除 | 狀態改為「已作廢」；**未出單品項一併刪除**，總金額重算為只含已出單品項 |
| 單號 | 不保留 | 保留 |
| 訂單列表／日結 | 不出現、不計入 | 出現，日結計入作廢張數 |
| 原因 | 不需填寫 | 必填，記錄操作者（稽核） |

## 2. 規則

- 未成立訂單的訂單頁只有「取消」按鈕（確認後刪除，回到訂單列表）；後端「作廢」也會擋下未成立的訂單，提示改用「取消」。
- 已成立訂單不論是否結帳，作廢區塊一律稱「作廢訂單」「作廢原因」（原本未結帳時稱「取消訂單」，易與新的「取消」混淆）。
- 已成立但仍有待出單品項時（出單失敗、手機加點），畫面上**沒有「取消」**：待出單品項以「確認訂單」出單或逐項「移除」；整張不要則「作廢」（含已出單品項）。
- **作廢時刪除未出單品項**（2026-10-13 使用者決議）：未出單品項廚房從未收到，作廢紀錄只保留已出單品項，總金額同步重算，與紙本出單一致、方便對帳。已結帳訂單不會有未出單品項（結帳前必須出完單）。
- 刪除時在伺服器日誌記錄操作者、訂單 ID、單號與品項數（資料庫不留紀錄，供事後查詢）。
- **單號不重排**：單號仍於建單時給定（今天營業日最大單號 + 1）。取消的是最新一張時，下一張沿用同號；中間的單被取消則留下空號（使用者接受，2026-10-13）。
- **既有資料不動**：v15 之前以「未確認出單，使用者取消」作廢的訂單維持原狀，避免與已完成的日結張數不一致。

## 3. 影響範圍

| 位置 | 變更 |
| --- | --- |
| 訂單詳情頁 | 「取消」確認文字說明會直接刪除；作廢區塊標題一律為「作廢訂單」 |
| 後端 | `CancelPendingItems` 只用於未成立訂單（刪除），已成立訂單擋下（原本會移除待出單品項，畫面上已無入口）；`Void` 擋下未成立訂單，並刪除未出單品項 |
| 日結頁 | 未結帳提示改為「請先結帳、作廢或取消後再日結」 |

**不變**：已成立訂單的作廢流程、報表（本來就不計作廢單）、出單。

## 4. 資料

- 不需 Migration（品項、加料本來就設定隨訂單連動刪除）。

## 5. 驗收標準

- 未成立訂單按「取消」後，訂單、品項、加料皆從資料庫刪除，訂單列表與日結不再出現。
- 取消最新一張後，下一張新單沿用同一單號。
- 未成立訂單無法作廢；已成立訂單照常作廢並記錄原因與操作者。
- 作廢後訂單只剩已出單品項，總金額只含已出單品項。
