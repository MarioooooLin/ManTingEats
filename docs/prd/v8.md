# PRD — ManTingEats v8（結帳折扣）

> 狀態：**已定案**（2026-10-07，依使用者逐項決議整理）。本文件擴充 [v6.md](v6.md) 的結帳流程。

## 1. 需求摘要

**目標**：熟客用餐、餐點出問題或招待時，結帳能給折扣，並留下紀錄供營收報表與事後對帳。

**使用者**：店長與員工**都可以**給折扣，**不設上限**（使用者決議）；每筆折扣記錄金額、原因與操作者。

## 2. 結帳視窗中的折扣

結帳視窗新增「給折扣」按鈕（平常收起，不影響一般結帳速度）。展開後：

| 方式 | 操作 | 例（原價 $487） |
| --- | --- | --- |
| **改收金額** | 輸入最後要收的金額 | 輸入 450 → 折扣 $37 |
| **打折** | 輸入折數：1～9 代表幾折、10～99 代表幾幾折 | 輸入 9 → 應收 $438（四捨五入到元） |
| **抹零**（按鈕） | 去掉個位數，原因自動選「抹零」 | → 應收 $480；原價已是整十時不顯示 |

- 畫面即時顯示「原價 → 折扣 → 應收」，之後照 v6 流程「收剛好」或輸入收款金額、顯示找零。
- 折扣後應收需為**整數**、**0 以上**且**小於原價**；應收 $0 即整單招待。
- **原因必選**（一鍵選擇）：熟客、抹零、招待、餐點問題、其他。
  - 「餐點問題」「其他」**必須填說明**（最多 100 字），例如「牛肉麵太鹹」。
  - 其他原因可選填說明。
- 可按「取消折扣」恢復原價。

### 2.1 餐點有問題

使用**整單折扣**處理（使用者選 A）：原因選「餐點問題」，說明寫哪道菜、什麼問題。需要重做時，照常加點出單，結帳時再以折扣折掉。不另做單一品項免費。

## 3. 資料與報表

- 訂單新增：折扣金額、折扣原因、說明、給折扣的操作者（需 Migration）。
- 訂單原本的「總金額」維持為品項＋加料的**原價**；**實收 = 原價 − 折扣**。
- **營收報表**：
  - 總營收與通路拆分改以**實收**計算。
  - 新增顯示「本期折扣總額」。
  - 品項、加料排行維持原價，因此「品項＋加料排行 − 折扣總額 = 總營收」。
- 訂單詳情顯示原價、折扣（原因、說明、操作者）與實收；訂單列表的金額欄顯示實收。
- 出單不受影響（結帳本來就不出單）。
- 收款金額與找零仍只在畫面計算、不存資料庫（v6 決議不變）。

## 4. 明確排除（本次不做）

- 不做單一品項免費或品項層級折扣。
- 不做折扣上限、折扣需店長核准。
- 不做結帳後修改或取消折扣（需作廢重開）。
- 不做依原因統計的折扣報表（資料已存，日後可加）。
